# Original runtime legal bindings

Original third-party legal text must remain unmodified. Collecting it does not
automatically approve a distribution or satisfy the native acceptance gates.

The frozen downloader is inventoried without executing archived Python code.
Its actual diagnostic library versions and native version APIs are compared to
immutable original source identities. Generated release-head metadata is checked
against the original release source, rather than assumed to equal the release
tag's commit. Official SQLite amalgamation hashes and full source identifiers
provide an independent check of the corresponding SQLite version.

Rust standard-library notices must cover incorporated dependencies, not merely
the Rust project's root MIT/Apache grants. Preserve the original detailed
`COPYRIGHT-library.html` from the checksum-verified official distribution for the
identified compiler source. The compiler archive is inspected, never installed
or executed. Do not substitute a generic notice with invented author/year data.

A deployment job's toolchain is not evidence of the binary's compiler. Oxipng's
release job retrieves an earlier compilation artifact. The actual macOS
compilation logs and artifacts must therefore be inspected independently. Match
the original compilation artifact executable hash to the locked release input
before associating its compiler version with that binary. Its original workflow
uses a rebuilt standard library, so include that exact toolchain's full original
standard-library legal table rather than inferring the host system's Rust version.

Retain checksum-bound original Oxipng release source and Cargo registry archives.
The complete release lock is a conservative source superset: build, test and
other-platform crates are not automatically represented as linked runtime
dependencies. Record original package license declarations and notices separately
from any remaining root-notice or binary-association findings.

Ready-component staging is an implementation input, not release approval.
The final application still requires an actual binary inventory, original-notice
associations, corresponding-source review and zero unresolved license findings.
Both native architectures, the final application manifest and installed DMG
must pass the independent autonomous release gate before publication.
